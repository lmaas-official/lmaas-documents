# AI Feature Specifications

Last checked: 2026-11-18 (Japanese original)

## AI models

| Item | Details |
|---|---|
| Type of model | Publicly available open LLMs (large language models) |
| Number listed | Over 1,000 (selected from the AI model hub "Hugging Face") |
| Main developers | Google (Gemma), OpenAI (gpt-oss), Meta (Llama), Alibaba (Qwen) and others |
| How to find models | Filter by task (inquiry handling, document summarization, etc.) and industry (healthcare, insurance, etc.) |
| Usage conditions shown | Whether commercial use, additional training and redistribution are allowed is shown for each model |
| License consent | For models that require consent, who consented and when is recorded |
| Size limit | Judged by both the "nB class" (the model's stated size) and the weight that fits on the GPU, for each plan ([plan-matrix](plan-matrix.md)) |
| AI execution engine | Ollama (all plans), vLLM (can be switched to on dedicated-GPU plans) |

The "nB class" is a category based on the size in the model's name (e.g. 8B). Some models are named 8B but are actually slightly larger, so the screen also shows the actual size.

## Internal document reference (RAG)

| Item | Details |
|---|---|
| Method | RAG (Retrieval-Augmented Generation). Relevant parts are searched from registered documents, and the AI uses them in its answers |
| Plans | All plans |
| Versioning | Reference data is managed by version, and you can choose which version to use |
| Updates | You can update only the RAG reference data, without additional training |

## Additional training (LoRA)

| Item | Details |
|---|---|
| Method | LoRA. Only a small "add-on" is trained, without changing the AI model itself |
| What it learns | How your registered Q&A and texts answer and are written |
| Length per document | Up to about 2,000 tokens (anything longer is cut off) |
| Settings | Just choose the training strength from "Low", "Standard" and "High". Training runs automatically |
| Number of runs | A set number per plan every 30 days (Personal / Starter / Starter Plus 5, Business 8, Business Plus 10). Additional runs: $5 each (excluding tax, customers outside Japan) / ¥800 each (excluding tax, customers in Japan) |
| Training-only mode | On dedicated-GPU plans, you can switch the server to training-only mode and train without a limit on the number of runs (chat is unavailable during that time) |
| Saved versions | Personal 3, Starter / Starter Plus 5, Business 7, Business Plus 10 |
| Going back | You can go back to a previous version, or to the base model alone |
| Models that cannot be trained | Some models, such as those in compressed formats, cannot be trained. Whether training is possible is shown on the screen |

## Training Data Creation

| Item | Details |
|---|---|
| Source documents | Word (.docx), Excel (.xlsx), PowerPoint (.pptx) and PDF. Older formats (.doc, .xls, .ppt), files with macros and password-protected files cannot be used |
| Size limits | Word, Excel and PowerPoint: up to 5MB per file. PDF: up to 20MB and 100 pages on Personal, Starter and Starter Plus; up to 30MB and 200 pages on Business and above |
| What is created | Excel "question" and "answer" columns become question-answer pairs; everything else becomes text split by heading or page. Long text is split automatically |
| Extraction methods | Choose between "Direct extraction" (turns Excel "question" and "answer" columns into question-answer pairs and excludes hidden sheets, rows and columns) and "MarkItDown" (converts the document to Markdown first, then splits it by heading, sheet, slide or page; the open-source converter runs inside the service). You can create data from the same document with both methods and compare them |
| Review | You can view the created data on the screen and export it as Markdown. The customer reviews it and sends only the selected items as training data |
| Uses | The data sent can be used for both additional training (LoRA) and internal document reference (RAG) |
| Where documents are read | Only inside the service. Documents are not sent to external AI services |
| Training runs | Not used (creation is a separate process from training) |
| Not covered | The contents of images and charts, and PDFs with no text (scanned images only). With Direct extraction, Excel's hidden sheets, rows and columns and PowerPoint's hidden slides are also excluded (they are read with MarkItDown) |
| Retention | Created data that is not sent as training data is deleted automatically after 30 days |

## Identifying AI-generated content

| Item | Details |
|---|---|
| On-screen display | Always shows that you are talking with an AI |
| API replies | A marker showing that the reply was generated by AI, plus a record number |
| Generation records | A signed record is created for each answer. It does not contain the text of the answer itself; it stores a fingerprint for matching. Kept for 180 days |
| Verification | You can check with the verification service whether an answer was created by lmaas.io's AI |

## How additional training (LoRA) relates to the AI execution engine for each model

Here are answers to common questions about using "additional training" with lmaas.io.

### Training and replying are separate mechanisms

- **Training** (creating the LoRA "add-on") is done on dedicated GPU servers for training.
- **The mechanism that produces replies** (the AI execution engine) is Ollama or vLLM. It applies the add-on created by training so it can be used in chat.
- The training mechanism is the same whether you choose Ollama or vLLM. Switching engines does not change how training is done.

### How the trained add-on is applied differs by engine

| AI execution engine | How it is applied | Notes |
|---|---|---|
| Ollama | The trained add-on is converted to Ollama's format and built into the base model | Available on all plans. Conversion and integration are automatic; no action is needed from the customer |
| vLLM | The trained add-on is loaded at run time during chat | Can be switched to on dedicated-GPU plans. No conversion is needed |

With either engine, trained add-ons are managed separately for each customer and are never used by other customers' AI.

### Models that can and cannot be trained

| Type of model | Additional training | Internal document reference (RAG) |
|---|---|---|
| Regular public models (Llama family, Qwen family, etc.) | Yes | Yes |
| Models in compressed formats (FP8, AWQ, GPTQ, etc.) | No | Yes |
| Models published only in a compressed format (GGUF) | No | Yes |

- Compressed formats reduce precision to make models lighter and smaller. They can be used for chat, but additional training needs the original precision, so such training is declined at the time of reservation.
- Even for models that cannot be trained, you can use internal document reference (RAG) alone.
- For newly published models, it may not yet be known whether training is supported. Whether a model can be trained is shown on the screen for each model.

### Continuing training from a previous version

- You can continue training from a version you have already created (continual training).
- When you continue, training builds on the results of the previous version. If you delete the previous version, you can no longer continue training from it.
- You can always go back to a previous version, or to the base model alone.

### Things to keep in mind

- The effect of additional training depends on the model you choose and the content of your training data. The effect is not guaranteed.
- The newer the model, the more likely it is that support in Ollama and vLLM, and support for training, are not yet in place. Please check the status on the screen.
